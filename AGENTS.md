## 1. Project Overview

**By The Handful** is a full-stack e-commerce web application selling artisanal dry fruits, nuts, berries, seeds, and curated gourmet gift hampers.

- **Frontend & Full-stack SSR:** [TanStack Start](https://tanstack.com/start) with [TanStack Router](https://tanstack.com/router) (file-based routing) and React 19.
- **Styling & UI:** Tailwind CSS v4, Radix UI primitives, Lucide React icons, and `tw-animate-css`.
- **Database & Auth:** [Supabase](https://supabase.com/) (PostgreSQL with Row-Level Security, Auth with JWT / Bearer tokens).
- **Payments:** [Razorpay](https://razorpay.com/) (Indian Payment Gateway: UPI, Netbanking, Cards, Wallets) via server-side order creation + frontend modal (`react-razorpay`) + server-side HMAC signature verification.
- **Build Tool:** Vite 8 with `@tanstack/react-start-plugin` and Nitro.

## 4. Key Architectural Patterns & Conventions

### 4.1 Server Functions (`createServerFn`)

All server-side operations (database queries requiring authorization, payment processing) are defined using TanStack Start's `createServerFn`:

- **File naming:** Place in `src/lib/*.functions.ts`.
- **Validation:** Always validate input data with `.validator(...)` or Zod.
- **Middleware:** Attach `.middleware([requireSupabaseAuth])` or `.middleware([requireAdminAuth])` to secure server execution.
- **Client calling:** Call directly from React components as async functions (e.g. `await createRazorpayOrder({ data: ... })`).

### 4.2 Supabase Clients & Security

There are three Supabase client scopes in the project:

1. **Client-side (Browser):** `src/integrations/supabase/client.ts` uses `VITE_SUPABASE_PUBLISHABLE_KEY` and handles user sessions.
2. **User-scoped Server Client:** `requireSupabaseAuth` in `src/integrations/supabase/auth-middleware.ts` receives the `Bearer <token>` from request headers and creates a scoped client. RLS policies apply strictly to the user (`auth.uid() = user_id`).
3. **Service Role (Admin) Server Client:** `src/integrations/supabase/client.server.ts` exposes `supabaseAdmin` using `SUPABASE_SERVICE_ROLE_KEY`. **Never** expose this to client code. Only import inside server handlers.

### 4.3 Payment & Checkout Flow

1. **Order Initiation (`/checkout`):** User reviews cart items and fills delivery address.
2. **Server Order Creation:** `createRazorpayOrder` in `checkout.functions.ts` initializes the Razorpay SDK, converts amount to paise (`amount * 100`), and creates a Razorpay order.
3. **Client Modal:** `react-razorpay` (`useRazorpay()`) opens the checkout overlay.
4. **Signature Verification:** On success, client calls `verifyRazorpayPayment` with `razorpay_order_id`, `razorpay_payment_id`, and `razorpay_signature`.
5. **Database Transaction:** Backend verifies the HMAC-SHA256 signature using `RAZORPAY_KEY_SECRET`. Upon match, it inserts rows into:
   - `orders` (status: `'processing'`, payment_status: `'paid'`)
   - `order_items`
   - `payments` (provider: `'razorpay'`, status: `'completed'`)

### 4.4 Row Level Security (RLS) Rules

When modifying or adding database tables:

- Always ensure `ENABLE ROW LEVEL SECURITY;` is present.
- Authenticated users must have matching `FOR SELECT` and `FOR INSERT` policies checking `auth.uid() = user_id`.
- Admins check `EXISTS (SELECT 1 FROM public.profiles WHERE profiles.id = auth.uid() AND profiles.is_admin = true)`.
- All database schema updates should be committed as numbered migration files in `supabase/migrations/`.

## 6. Rules for AI Agents

1. **Do not modify `src/routeTree.gen.ts` directly:** This file is generated automatically by TanStack Router when routes in `src/routes/` are modified.
2. **Preserve SSR Boundaries:** Do not use `window`, `document`, or `localStorage` during SSR without guarding with `typeof window !== 'undefined'` or React effects.
3. **Database schema changes:** Never modify remote DB without creating a matching SQL file in `supabase/migrations/`. Ensure RLS policies and `GRANT` statements cover both `SELECT` and `INSERT` operations.
4. **Payment security:** Never trust client-reported payment totals. Calculate prices and verify HMAC signatures exclusively on the server.
